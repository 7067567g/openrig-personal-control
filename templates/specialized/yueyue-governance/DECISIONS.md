# DECISIONS — 月月bot 微信桥单用户可靠性专项治理

## 1. 决策账本

### D-001（Round 1）单用户范围与排除项

- **决策**：本 run 以单 owner、可信本机为前提；不做多用户 ACL/审批/路径沙箱/远程鉴权加固。
- **理由**：连接方式固定为单人；这些工作会显著增加操作与维护成本，不进入本轮。
- **影响面**：SPEC §1 范围与反目标。
- **状态**：生效。

### D-002（Round 1）便利性不可回退

- **决策**：任何修复不得新增用户确认步骤、不得新增周期性系统消息、不得改变现有命令入口与对话风格。
- **理由**：治理目标是让日常使用更稳，不是更复杂。
- **影响面**：所有 WS 的实现选择。
- **状态**：生效。

### D-003（Round 1）执行面与心跳

- **决策**：使用 OpenRig 单 DSH seat 执行；由 daemon-native watchdog `periodic-reminder` 每 600 秒唤醒；seat 以 `STATE.md` 为唯一进度源，自行推进直到 `DONE`/`BLOCKED`。
- **理由**：不依赖主会话参与，能跨多轮持续作业；单 seat 足够处理本专项，避免多 seat 写冲突。
- **影响面**：执行方式、证据落点、停止条件。
- **状态**：生效。

### D-004（Round 1）变更与回滚

- **决策**：先在 `governance-20261110/staging/wechat-bridge-v2/` 修改并跑测试；WS-7 通过后才应用到 live；应用前必须有 pre 快照，应用后必须能一键回滚。
- **理由**：项目非 git 仓库，必须用快照保证可回滚。
- **影响面**：WS-0/WS-7/WS-8。
- **状态**：生效。
