# SPEC — 方法论实战验证 + 消费闭环（P2）

## 0. 分层声明

baseline: composite/knowledge-pipeline@1.0.0
contracts: research@1.0.0, optimize@1.0.0, verify@1.0.0

> 特化规则，优先于通用手册。前置：P1（kb-debt）已完成，方法论正文已在 `05-methodology/`。

## 1. 任务

用新入库的方法论指导实现一个**真实可运行的交互式应用原型**，并全程记录**真实 KB 查询**，把日志回写 Map4 #32 消费闭环。

1. 从 `05-methodology/` 方法论正文中抽取全部原则，逐条给出「采用 / 不适用（附理由）」；
2. 按方法论实现一个原型（建议：离线单文件网页应用，落在 run 目录，能本地跑通）；
3. 实现过程中每个真实问题都查 KB，记录：日期｜查询人/Agent｜问题｜命中文档｜是否解决｜耗时；
4. ≥10 条真实查询记录回写 `05-methodology/kb-evolution-direction-assessment.md` 阶段 2 执行记录（#32）。

## 2. 写权限

| 路径 | 用途 |
| --- | --- |
| `runs/<RUN-ID>/**` | 原型、报告、日志（主战场） |
| `05-methodology/**` | 消费日志回写、方法论实战验证记录（只追加，不改历史结论） |

白名单外只读；不碰项目仓。

## 3. 全内容 / 证据

- 方法论原则 100% 处置（逐条表格 + 证据）。
- 查询日志只记真实发生的查询；维护性 `grep`、核验动作不计入；不补记、不虚构。
- 原型必须给出可复跑命令与输出（构建、启动、至少 1 条功能自测）。
- 回写 #32 时遵守其既有字段与「不虚构」口径；如与既有记录冲突，先记 ISSUES。

## 4. 禁止

- 不虚构查询日志与测试结果；不把"应该能跑"当证据；
- 不改白名单外路径；不 push；不删除任何已有文档。

## 5. DoD

- 方法论原则处置表 100%；
- 原型可运行 + 自测证据；
- ≥10 条真实查询日志写入 `kb-evolution-direction-assessment.md` 阶段 2；
- 相关门禁（`validate all` / `genviews --check`）绿；
- `reports/final.md` 汇总。
