# SPEC — KB 全库断言核验（P4，长跑）

## 0. 分层声明

baseline: none — 直接原子组合
contracts: audit@1.0.0, verify@1.0.0

> 特化规则，优先于通用手册。目标：把 KB 正式文档里"可被现实打脸"的断言逐条核一遍。

## 1. 任务

对 KB 全部正式文档（约 108 篇）做**只读**断言核验，逐篇产出结论：

1. 抽取可核断言：路径/文件名、命令、版本、跨文档引用、对项目代码行为的描述、数据格式字段；
2. 对照实际仓库与环境验证（文件存在性、脚本可跑、引用可解析、代码行为一致）；
3. 每篇给结论：`一致 / 不一致 / 不可核（原因）`，不一致给最小证据。

## 2. 写权限

| 路径 | 用途 |
| --- | --- |
| `runs/<RUN-ID>/**` | 逐篇结论表、不一致清单、报告（唯一可写） |
| KB 正式域 | **只读**；发现的问题只登记，不改正文 |

## 3. 全内容要求

- 108/108 篇必须出现结论，不许抽样；允许分批（每批 15-20 篇）但必须覆盖全量；
- 每篇至少核 1 条断言；无任何可核断言的文档标 `不可核（纯方法论）` 并说明。

## 4. 证据

- 每条不一致：文档 + 行号/章节 + 验证命令 + 实际结果；
- 每条"一致"：至少给验证方式（命令/路径），不接受空口。

## 5. 禁止

- 不改 KB 正文、不动项目仓、不 push；
- 不把"找不到反例"当一致；不可核就写不可核。

## 6. DoD

- 108/108 结论表（`reports/claim-verify-ledger.md`）；
- 不一致清单（含证据）与建议处置（另开票/修正/忽略）；
- 汇总统计（一致/不一致/不可核比例）。
