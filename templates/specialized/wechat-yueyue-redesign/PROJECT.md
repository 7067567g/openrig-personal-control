## 1. 目标与成功判据

- **G1 证据盘点**：读完 QQ 桥历史文档与当前微信桥代码，形成事实清单和来源指针。
- **G2 单窗口产品判断**：从常识出发，明确必须补 / 应该删 / 暂缓的功能。
- **G3 v2 设计与实现**：状态、队列、后台、steer、取消、重试、菜单、三模式、长回复交付均可用。
- **G4 验证**：静态检查 + 真实 DSH web 会话 + 队列/状态/模式/长回复的离线测试。

**反目标**：不做安全/权限大工程；不做 Web 控制台；不做周期性心跳；不把长回复转图片。

## 2. 范围

### 2.1 范围内

- 微信桥运行循环、任务调度、状态卡、控制命令、交付策略；
- 当前 `bridge-fork` 的兼容升级与回滚；
- 必要的测试和文档。

### 2.2 范围外

- 微信协议本身、iLink 登录细节；
- 多联系人 ACL、群聊、审批流；
- 生图、语音、定时提醒等后续增量。
